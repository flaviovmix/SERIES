### Tela 4 (07:33 a 09:26, 01:52)

E isso leva a gente para a próxima tela, então aperte o próximo. Então como que a gente informa essa lista de lugares na mão, para ter essa liberdade toda de não ficar presa a uma pasta só? E para fazer isso, a gente apresenta a opção D do comando Java C, que é o nosso compilador. E o que essa opção faz? Ela manda o compilador escrever os arquivos class em uma pasta de saída dedicada e não ali do lado do código fonte. E a mágica é que ele cria as pastas do pacote sozinho lá dentro. Ah, então ele já cria aquele caminho brf, fax, tarefas... Tudo sozinho. Assim, o comando Java com aquela opção Cp só precisa apontar para essa pasta de saída na hora de rodar. Entendi. Mas, para aí, explica para a gente por que separar é tão importante. Não seria mais fácil deixar tudo misturado ali e poupar comando? Parece, mas não. Tem duas razões muito práticas para isso, não é só frescura de etiqueta. A primeira é que a pasta de saída pode ser apagada e refeita a qualquer momento. Tudo que está ali nasce do código fonte, é descartável. Verdade, é só compilar de novo. E a segunda razão, que é até um gancho para nossa próxima etapa, é que o histórico de código só guarda o código fonte. Ele não tem que guardar saída compilada. Faz todo sentido. Se você mistura os dois na mesma pasta, o histórico acaba guardando arquivos class sem querer e isso causa problemas chatos no futuro. Entendido.
